A "how I chain models" post is a workflow tip and it is banned. The same content is legal as a
build-in-public experiment report, which is confirmed Exception 2 in the no-tool-tips rule and
the archetype behind the ~30K agents post.

Lior has the real experiment. June 2026: Anthropic split the billing for outside agents, the math
changed, he replaced OpenClaw with Hermes plus a Codex subscription, and the swap took minutes
because his whole setup is file-based and local. That is the post. The reason he could switch
engines in an evening is the same reason he does not have to pick a side now.

So the post is not about Astra. It is about why the question is a procurement question, and Astra
is the news peg that makes it timely.

**The "vs." :** locked into one model vs. owning the context and renting the engine.

## Draft

--- POST STARTS ---

Last June I swapped my entire agent stack in one evening.

Nothing broke.

Anthropic changed how outside agents get billed, the math changed, so we moved. Hermes and Codex went in where the old setup had been.

It took an evening because the part that matters never lived inside the model.

It lives in a folder. Plain text files that describe the company, the rules, the voice, the way we work. A new model reads that folder and starts from where the last one stopped.

That is the entire connection between models. No clever integration. A context you own, and a socket the engine plugs into.

Which is why the Astra versus Claude argument reads strange from an operator seat.

We do not run one model. We route.

Long browser jobs that have to run for an hour with nobody watching go to Astra.

Shipping code goes to Codex.

Judgment on a long document goes to whichever engine reads best this month.

An engine is a supplier. Suppliers get compared on price and performance, and they get replaced when a better one shows up. Nobody asks a factory which drill brand it is loyal to.

The real trap is a setup your context cannot walk out of.

Where does yours live right now?
