When delivering any post, reply, or comment draft (LinkedIn, X, Bluesky, IG caption, anywhere), wrap the copyable text in explicit delimiter lines:

--- POST STARTS ---
(the draft, plain text)
--- POST ENDS ---

For replies/comments use --- REPLY STARTS --- / --- REPLY ENDS ---.

**Why:** Reut said (2026-07-08) she can't tell where a drafted post starts and ends when it's mixed into my prose. Reconfirmed 2026-08-03 for LinkedIn replies ("תמיד תעשה לי מאיפה התגובה מתחילה ואיפה נגמרת"). Reconfirmed AGAIN 2026-08-06 after several chat iterations were delivered bare ("תחזור לכתוב לי תחילת פוסט וסוף פוסט תמיד") — this applies to EVERY draft type, EVERY iteration in chat, always, without being asked. Do not drop the markers mid-conversation even when iterating rapidly on small edits.

**UPDATED 2026-10-25 (Reut: "כשאני מבקשת ממך לכתוב לי פוסטים שים אותם בפורמט של העתק"):** the draft text itself goes in a fenced code block (```text) so the app shows a copy button. Markers sit outside the block, on the lines just above and below it, so they are never copied. This applies to every iteration, not only the final one. The ▮ cursor stays inside the block where the rules require it.

**How to apply:** Markers on their own lines, nothing else on them. Plain text inside the code block, never blockquotes per [[feedback-reply-formatting]]. If delivering multiple drafts, wrap each one separately. Optional add-ons go inside the markers only if they're part of the recommended final text; otherwise present them as a separate marked block.
