Before scout-day or scout-replies writes a single word, every topic gets mapped to 5 fields:

1. **Topic Name** — short, clear working title.
2. **Description** — 2-3 sentences: the angle and why Lior's audience cares.
3. **Pillar** — which of Lior's 4-5 content pillars this maps to (founder journey, scaling SaaS, hiring/firing, AI in ops, building in public). Every topic must belong to one.
4. **Perspective** — the angle. Pick ONE: contrarian / educational / authoritative / storytelling / behind-the-scenes / opinion-hot-take. Same topic hits totally differently per perspective.
5. **Vehicle** — the format. Pick from proven bank: value tweet / story post / thread / hot take tweet / doc screenshot / listicle / long-form / hand-drawn photo. Pulled based on what's winning that week.

**Why:** Wiz of Ecom system (2026-05-01 thread, 147K views) — skipping any of these = content comes out generic. The structure forces intentionality. A "story post about firing someone" is different from a "hot take about firing fast" is different from a "BTS thread about how we restructured the team." Same raw topic, different field combos = different audiences hit.

**How to apply:**
- Add this as a required preamble in scout-day output BEFORE the 5 drafts. Show the 5 fields per post.
- If Reut sees a draft missing any field, send it back.
- Cross-check Perspective against the week's winning perspective from x-analyst-weekly. If data shows BTS is winning this week, weight 3 of 5 posts to BTS perspective.
- Cross-check Vehicle against the week's winning vehicle. Don't default to plain text every time.
